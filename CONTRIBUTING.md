# Contributing

1. Read `.kiro/steering/` and update the relevant spec in `.kiro/specs/<feature>/` before changing a
   major feature. Record acceptance criteria first.
2. One feature per branch. Keep changes small and reviewable.
3. Run before opening a PR:

```bash
make backend-lint backend-test
make frontend-check frontend-test frontend-build
make mcp-lint mcp-test
```

4. Never commit secrets or real API tokens. `.env` is ignored; `.env.example` contains placeholders.
5. Never remove `.kiro/` from version control. Never add it to `.gitignore`.
6. Do not weaken assertions, skip tests or suppress type errors to make a check pass. If a check
   cannot run, say so.
7. Update `BUILD_STATUS.md` with what actually ran. Do not mark work VERIFIED without evidence.
8. Keep repository content untrusted: no code execution, no shell interpolation, no unrestricted
   agent tools.
9. Label actual, inferred and AI-suggested output. Missing data must remain visibly missing.

## Adding a migration

```bash
cd backend
python -m alembic revision --autogenerate -m "describe the change"
python -m alembic upgrade head
python -m alembic downgrade -1
```

Review autogenerated SQL; do not rely on autogenerate for data migrations.

## Adding an MCP tool

Add the function to `mcp-server/nexus_mcp/tools.py`, register it in `server.py`, extend
`TOOL_FUNCTIONS`, add a mocked-transport test, and update `mcp-server/README.md` and
`docs/mcp-setup.md`. Default to read-only.
